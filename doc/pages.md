# Pages

Every public URL the site serves, the template chain that builds it, the data sources it reads, the SCSS partials that style it, and the JS modules it loads.

Use this as a debugging map: "the homepage hero looks broken" → start at the homepage row.

## Bags — `/bags/` and `/bags/<slug>/`

| What                | Where                                       |
| ------------------- | ------------------------------------------- |
| Content files       | `content/bags/_index.md` (intro) + `content/bags/<slug>/_index.md` (one per bag) |
| Template            | `layouts/bags/list.html` (branches on `.Path`: index vs single bag) |
| Data                | member articles' `bags: {<slug>: <order>}` frontmatter |
| SCSS                | `bags.scss`                                 |
| JS                  | `tag-filter.js` + `bags-filter.js` (index only) |

A bag is a curated pack of articles around one use case. Membership is
declared on the *article* (`bags: {<bag-slug>: <order>}`); the bag page
queries all articles carrying its slug and sorts them by the order value.
The index lists every bag with a search bar and tag pills (tags aggregated
from member articles).

## Article graph — `/article-graph/`

| What                | Where                                       |
| ------------------- | ------------------------------------------- |
| Content file        | `content/article-graph/index.md` (`type: "article-graph"`) |
| Template            | `layouts/article-graph/single.html`         |
| Data                | all articles' `tags` + `{{</* ref */>}}` cross-links |
| JS                  | vendored d3 + `force-graph.js` + `article-graph.js` |

Force-directed graph of the published articles: nodes = articles, edges =
shared tags and explicit cross-references. Linked from `/articles/` when
`params.articles.showGraph` is true. Like `/collab/`, the node/link data is
built by the template into a JSON `<script>` block; the page module renders it.

## Tools index — `/tools/`

| What                | Where                                       |
| ------------------- | ------------------------------------------- |
| Content file        | `content/tools/_index.md`                   |
| Template            | `layouts/tools/list.html`                   |
| Partials            | `partials/search_bar.html`, `partials/flavours_box.html`, `partials/articles/article_thumb.html` |
| Data                | Child pages' frontmatter (`tags`, `category`, `platforms`), `hugo.Data.tags.keywords` |
| SCSS                | `tools.scss`, `cards.scss` (grid + card classes reused), `search.scss`, `tags.scss`, `page-titles.scss` |
| JS                  | `tag-filter.js`, `tools-filter.js`          |

Card grid identical to the homepage article grid. Tools share the article
tag vocabulary (`tags:` frontmatter, `data/tags.yml` labels, `tags.scss`
colours) but filtering stays per-section: the flavours box aggregates tags
from tool pages only, and tag badges link to `/tools/?tag=…` while the same
tag on an article links to `/articles/?tag=…`. The `/articles/` pill cloud is
unaffected (it aggregates from `Type == "article"` pages only), and the
global navbar search never indexes tools (`_default/index.json` filters on
`Section == "articles"`). The page search bar filters tool cards only,
client-side.

| ------------------- | ------------------------------------------- |
| Template            | `layouts/tags/list.html` (redirect shim)    |

## Reading the table

If a page renders wrong, the columns above tell you exactly which files to open. Examples:

- **Card layout broken on the homepage?** → `partials/articles/cards.html` and `cards.scss`.
- **Author page missing articles?** → `_content.gotmpl` produced the page, `single.html` filters `site.RegularPages` by `authors`. Check the article frontmatter `authors:` array.
- **Search returns nothing?** → `navbar-search.js` consumes `/index.json`; if missing, `_default/index.json` failed to render.
